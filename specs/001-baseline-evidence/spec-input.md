# Input for Spec Kit Assistant — HDL-01

استخدم هذا النص عند تشغيل مرحلة **Specification** في Spec Kit Assistant إذا كانت الأداة تريد إنشاء/تحديث `spec.md`.

---
Parent roadmap: `ROADMAP.md` → `HDL-01`.
Feature: **خط الأساس وخريطة الموجود والأدلة** (Baseline, Existing-Capability Map, and Evidence).
Phase: المرحلة 0 — الأساس.
Dependencies: none.
Work classification: Existing — Audit & Polish.

اكتب مواصفة وظيفية لثيم هديل على سلة. هديل ثيم واحد عام بنواة مشتركة وأربعة Presets. ترتيب القرار: زيادة التحويل، ثم سهولة التخصيص وتنوع الأشكال، ثم الجمال والحركة.

**الوصف المبسط:** نفهم حالة ثيم هديل الحالية بدقة قبل أي تطوير: ما الموجود فعلًا، ما يعمل، ما هو ناقص، ما حجمه، وما الأدلة التي سنستخدمها بعد كل تعديل.

**القيمة:** يمنع إعادة بناء ميزات موجودة، ويكشف التعارضات والحجم والمخاطر مبكرًا، ويعطي كل وكيل نقطة بداية واحدة موثوقة.

**داخل النطاق:**
- جرد صفحات الثيم ومكوناته وإعداداته العامة والخاصة.
- تصنيف كل قدرة إلى: موجود ويحتاج تحسين، مطلوب بناؤه، تجربة جدوى، أو مؤجل.
- تسجيل حجم ملفات البناء الحالية وأثقل CSS وJavaScript والأصول.
- تسجيل نتيجة أوامر البناء والفحص الحالية قبل أي تعديل.
- إنشاء خريطة تربط صفحات Figma بملفات الكود وصفحات معاينة سلة.
- توثيق الفروع المفتوحة والتعديلات غير المدمجة والمخاطر المعروفة.

**خارج النطاق:**
- إعادة تصميم الواجهات أو تنفيذ ميزات جديدة.
- حل جميع العيوب المكتشفة في نفس المواصفة.
- تغيير بنية المشروع دون خطة مستقلة.

**المتطلبات التي لا يجوز إسقاطها:**
- إنشاء سجل مركزي لكل صفحة ومكون وإعداد مهم في الثيم مع حالته الحالية.
- ربط كل ميزة كبيرة بمكانها في المصدر ومخرجات البناء، من دون تعديل ملفات `public` يدويًا.
- تسجيل نتائج `npx webpack --mode production` و`node scripts/check-theme.mjs --build` كما هي قبل أي إصلاح.
- قياس حجم الحزمة بالطريقة المتاحة محليًا، مع تمييز ما هو مؤكد عما يحتاج تأكيدًا من سلة.
- توثيق الأدلة المقبولة لكل نوع تغيير: كود، بناء، لقطة معاينة سلة، فيديو تفاعل، أو قياس أداء.
- إنشاء قائمة مخاطر مرتبة حسب تأثيرها على الإطلاق: الحجم، الأداء، الهوية، RTL/LTR، المعاينة، والفروع.
- عدم إعادة بناء أي عنصر قبل تصنيفه وفق مبدأ Preserve, Audit, Then Improve.

اجعل المواصفة:
- مفهومة لمالك غير تقني.
- مستقلة وقابلة للاختبار.
- Mobile-first وArabic/RTL-first مع English/LTR parity.
- ملتزمة بدستور `.specify/memory/constitution.md` و`AGENTS.md`.
- تبدأ بفحص الموجود وتصنيف Existing/Build/Spike/Deferred.
- لا تختار تقنية التنفيذ؛ هذا للـPlan.
- تحتوي بوابة Figma إلزامية قبل Plan للواجهات المرئية، مع `design.md` وNode IDs وموافقة المالك.
- تشترط production build وtheme guard ومعاينة سلة الحقيقية.
- تمنع نسخ كود/أصول/هوية Kalles أو رائد.
- تمنع أرقام social proof الوهمية في الإنتاج.
- تذكر أثر الحجم والأداء والوصول كمعيار قبول.
