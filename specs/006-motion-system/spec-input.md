# Input for Spec Kit Assistant — HDL-06

استخدم هذا النص عند تشغيل مرحلة **Specification** في Spec Kit Assistant إذا كانت الأداة تريد إنشاء/تحديث `spec.md`.

---
Parent roadmap: `ROADMAP.md` → `HDL-06`.
Feature: **نظام الحركة بثلاثة مستويات** (Motion System with Three Merchant Levels).
Phase: المرحلة 0 — الأساس.
Dependencies: HDL-02, HDL-03, HDL-05.
Work classification: Existing — Audit & Polish + Build.

اكتب مواصفة وظيفية لثيم هديل على سلة. هديل ثيم واحد عام بنواة مشتركة وأربعة Presets. ترتيب القرار: زيادة التحويل، ثم سهولة التخصيص وتنوع الأشكال، ثم الجمال والحركة.

**الوصف المبسط:** نوحّد الحركات في نظام هادئ أو متوازن أو غني بدل أن يضيف كل مكون أنيميشن خاصًا به.

**القيمة:** يعطي اختلافًا بصريًا قويًا مع الحفاظ على السرعة وعدم إزعاج المستخدم.

**داخل النطاق:**
- Motion tokens للمدة والتسارع والمسافة والشفافية.
- ثلاثة مستويات: هادئ، متوازن، غني.
- حركات الظهور والـHover والـDrawers والسلايدر والتغذية الراجعة.
- تقليل أو تعطيل الحركة على الجوال وعند `prefers-reduced-motion`.
- قائمة الحركات المسموحة والممنوعة.
- قياس أثر الحركة على الأداء.

**خارج النطاق:**
- حركات زخرفية تخفي المحتوى أو تؤخر الشراء.
- مكتبات جديدة كبيرة لمجرد مؤثر واحد.
- تشغيل الحركة الإجبارية لمن يطلب reduced motion.

**المتطلبات التي لا يجوز إسقاطها:**
- استخدام كل الحركات Tokens مشتركة لا أرقامًا عشوائية لكل مكون.
- كون المستوى المتوازن هو الافتراضي.
- تقليل `prefers-reduced-motion` للحركة تلقائيًا حتى لو اختار التاجر المستوى الغني.
- عدم تأخير حركة ظهور السعر أو زر الشراء أو نتائج البحث.
- عدم اعتماد وظيفة على Hover في أجهزة اللمس.
- عدم إضافة Layout Shift ملحوظ بسبب الحركة.
- إمكانية تعطيل الحركات الثقيلة على الجوال.
- توثيق مكتبات الحركة المستخدمة حاليًا وتقرير الإبقاء أو الاستبدال.

**قرارات refinement المعتمدة قبل Figma Revision 1:**
- المستويات الثلاثة فقط هي `calm` و`balanced` و`rich`، والحدود القصوى للحركة غير المستمرة هي 160ms و240ms و400ms على الترتيب.
- إعدادات HDL-06 الجديدة هي `motion_level` و`motion_reduce_mobile` فقط؛ لا يوجد Toggle مستقل للـreveal.
- `motion_reduce_mobile` مفعّل افتراضيًا ويقيد Rich على الجوال إلى سلوك Balanced في reveal/hover، من دون تعطيل feedback أو loading/error.
- `prefers-reduced-motion` هو أعلى أولوية، ويجب أن يستجيب لتغير التفضيل أثناء الجلسة، ويوقف reveal والتمرير السلس والحركات المتكررة غير الضرورية.
- المحتوى التجاري الحرج ظاهر وقابل للتفاعل عند 0ms، ويبدأ feedback الناتج عن فعل المستخدم خلال 100ms، وLayout Shift المنسوب للحركة يساوي صفرًا.
- لا توجد حركة جذب دورية للـCTA. يبقى `product_add_to_cart_animation` كـfeedback بعد فعل المستخدم، ويبقى `product_add_to_cart_animation_interval` كمعرّف توافق قديم بلا مؤقت دوري.
- الحركات الاتجاهية تستخدم logical start/end فقط؛ fade/scale/spinner والصور والشعارات لا تنعكس.
- انتقالات Salla/Swiper الداخلية التي لا توجد لها واجهة مثبتة تبقى Platform-owned Spike، ولا تُعالج بـoverride هش.
- لا Dependency أو Webpack entry أو طلب شبكة جديد. قرار keep/remove لمكتبة الحركة الحالية يعتمد على القياس في Plan.

اجعل المواصفة:
- مفهومة لمالك غير تقني.
- مستقلة وقابلة للاختبار.
- Mobile-first وArabic/RTL-first مع English/LTR parity.
- ملتزمة بدستور `.specify/memory/constitution.md` و`AGENTS.md`.
- تبدأ بفحص الموجود وتصنيف Existing/Build/Spike/Deferred.
- لا تختار تقنية التنفيذ؛ هذا للـPlan.
- تحتوي بوابة Figma إلزامية قبل Plan للواجهات المرئية، مع `design.md` وNode IDs وموافقة المالك.
- تشترط production build وtheme guard ومعاينة سلة الحقيقية.
- تمنع نسخ كود/أصول/هوية Kalles أو رائد.
- تمنع أرقام social proof الوهمية في الإنتاج.
- تذكر أثر الحجم والأداء والوصول كمعيار قبول.
