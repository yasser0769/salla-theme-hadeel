# Input for Spec Kit Assistant — HDL-03

استخدم هذا النص عند تشغيل مرحلة **Specification** في Spec Kit Assistant إذا كانت الأداة تريد إنشاء/تحديث `spec.md`.

---
Parent roadmap: `ROADMAP.md` → `HDL-03`.
Feature: **هندسة الإعدادات ومحرك التصميمات الجاهزة** (Settings Architecture and Preset Engine).
Phase: المرحلة 0 — الأساس.
Dependencies: HDL-01, HDL-02.
Work classification: Existing — Audit & Polish + Build.

اكتب مواصفة وظيفية لثيم هديل على سلة. هديل ثيم واحد عام بنواة مشتركة وأربعة Presets. ترتيب القرار: زيادة التحويل، ثم سهولة التخصيص وتنوع الأشكال، ثم الجمال والحركة.

**الوصف المبسط:** ننظم كثرة خيارات هديل بطريقة سهلة: إعدادات عامة واضحة، خيارات متقدمة مخفية، وإعداد تصميم جاهز يغيّر الشخصية البصرية من نواة واحدة.

**القيمة:** يعطي التاجر قوة قريبة من Kalles دون أن يضيع بين مئات الحقول، ويحافظ على ثيم واحد سهل الصيانة.

**داخل النطاق:**
- تقسيم الإعدادات العامة إلى مجموعات مفهومة.
- تعريف الفرق بين إعدادات الثيم العامة وإعدادات كل مكون.
- إنشاء Design Tokens وDefaults للتصميمات الأربعة.
- خيار Follow Preset مقابل Custom داخل المكونات المهمة.
- استخدام الشروط لإظهار الخيارات المتقدمة عند الحاجة.
- توثيق كل Setting ID ومعناه ومالكه وقيمته الافتراضية.

**خارج النطاق:**
- تطبيق خارجي للتحكم البصري بالثيم.
- استيراد متجر ديمو كامل تلقائيًا ما لم تثبت سلة ذلك بتجربة جدوى.
- خيارات لا تغير تجربة حقيقية أو تربك التاجر.

**المتطلبات التي لا يجوز إسقاطها:**
- عرض الإعدادات الأساسية قبل المتقدمة في كل مجموعة.
- بقاء التصميمات الأربعة Presets داخل ثيم واحد دون نسخ كود مستقلة.
- تطبيق Presets قيمًا افتراضية متناسقة للألوان والمسافات والحواف والحركة والهيدر والبطاقات.
- السماح للمكون المهم باتباع الـPreset أو اختيار Variant يدويًا عندما يكون ذلك مفيدًا.
- كون كل Setting ID فريدًا ومستقرًا وموثقًا في Settings Registry.
- ترجمة جميع أسماء الإعدادات ووصفها للعربية والإنجليزية.
- منع القيم الافتراضية تركيبة غير مقروءة أو مكسورة على الجوال.
- عدم اعتماد الخيارات البصرية العادية على تطبيق أو خدمة خارجية.
- إنشاء Spike منفصل لأي ادعاء بأن اختيارًا واحدًا يعيد ترتيب الصفحة أو يستورد محتوى ديمو.

اجعل المواصفة:
- مفهومة لمالك غير تقني.
- مستقلة وقابلة للاختبار.
- Mobile-first وArabic/RTL-first مع English/LTR parity.
- ملتزمة بدستور `.specify/memory/constitution.md` و`AGENTS.md`.
- تبدأ بفحص الموجود وتصنيف Existing/Build/Spike/Deferred.
- لا تختار تقنية التنفيذ؛ هذا للـPlan.
- تحتوي بوابة Figma إلزامية قبل Plan للواجهات المرئية، مع `design.md` وNode IDs وموافقة المالك.
- تشترط production build وtheme guard ومعاينة سلة الحقيقية.
- تمنع نسخ كود/أصول/هوية Kalles أو رائد.
- تمنع أرقام social proof الوهمية في الإنتاج.
- تذكر أثر الحجم والأداء والوصول كمعيار قبول.
