# Input for Spec Kit Assistant — HDL-02

استخدم هذا النص عند تشغيل مرحلة **Specification** في Spec Kit Assistant إذا كانت الأداة تريد إنشاء/تحديث `spec.md`.

---
Parent roadmap: `ROADMAP.md` → `HDL-02`.
Feature: **نظام تصميم Figma وبوابة الموافقة البصرية** (Figma Design System and Visual Approval Gate).
Phase: المرحلة 0 — الأساس.
Dependencies: HDL-01.
Work classification: Build.

اكتب مواصفة وظيفية لثيم هديل على سلة. هديل ثيم واحد عام بنواة مشتركة وأربعة Presets. ترتيب القرار: زيادة التحويل، ثم سهولة التخصيص وتنوع الأشكال، ثم الجمال والحركة.

**الوصف المبسط:** نبني في Figma نظامًا واضحًا لكل العناصر المتكررة، ونضع قاعدة تمنع بدء تنفيذ أي واجهة قبل أن تراها وتوافق عليها.

**القيمة:** يجعلك تشاهد النتيجة قبل البرمجة، يقلل التعديلات المكلفة، ويوحّد الألوان والمسافات والحالات عبر التصميمات الأربعة.

**داخل النطاق:**
- تنظيم ملف Figma إلى صفحات Foundations وComponents وFlows وPresets وQA.
- تعريف الألوان، المسافات، الحواف، الشبكات، الأزرار، الحقول، الأيقونات، وأسلوب الصور.
- إنشاء مكونات Figma بخصائص وVariants تعكس خيارات هديل الواقعية.
- تصميم الحالات الأساسية: عادي، hover، focus، loading، empty، error، disabled، sold out.
- تحديد آلية اعتماد المالك وربط Node IDs بكل spec.
- تعريف طريقة توثيق إعدادات الجوال والكمبيوتر وRTL/LTR.

**خارج النطاق:**
- تصميم كل صفحات المشروع كاملة في دفعة واحدة.
- تصميم لوحة تحكم جديدة لسلة؛ نستخدم حقول سلة ونوثقها فقط.
- تنفيذ الكود قبل اعتماد البوابة البصرية.

**المتطلبات التي لا يجوز إسقاطها:**
- يكون لكل مواصفة مرئية ملف `design.md` يذكر رابط Figma وNode IDs وحالة الاعتماد.
- تصميم العربية على الجوال أولًا، ثم العربية على الكمبيوتر، ثم التحقق من الإنجليزية LTR.
- عدم اعتبار اللقطة الثابتة كافية للعناصر التفاعلية؛ يجب توضيح الانتقالات والحالات والسلوك.
- تعكس Variants في Figma الخيارات التي يمكن تنفيذها فعلًا في سلة، وأي خيار غير مؤكد يعلّم Spike.
- توفير صفحة Settings Matrix تربط كل خاصية مرئية بإعداد التاجر ومكانه: عام أو داخل المكون.
- استخدام أسماء مكونات ثابتة مرتبطة بمعرفات المواصفات مثل `HDL-09/SearchDrawer`.
- احتواء كل شاشة معتمدة على ملاحظة Approved for Implementation وتاريخ وموافقة المالك.
- تسجيل أي اختلاف لاحق بين Figma ومعاينة سلة مع سببه وموافقة المالك.

اجعل المواصفة:
- مفهومة لمالك غير تقني.
- مستقلة وقابلة للاختبار.
- Mobile-first وArabic/RTL-first مع English/LTR parity.
- ملتزمة بدستور `.specify/memory/constitution.md` و`AGENTS.md`.
- تبدأ بفحص الموجود وتصنيف Existing/Build/Spike/Deferred.
- لا تختار تقنية التنفيذ؛ هذا للـPlan.
- تحتوي بوابة Figma إلزامية قبل Plan للواجهات المرئية، مع `design.md` وNode IDs وموافقة المالك.
- تشترط production build وtheme guard ومعاينة سلة الحقيقية.
- تمنع نسخ كود/أصول/هوية Kalles أو رائد.
- تمنع أرقام social proof الوهمية في الإنتاج.
- تذكر أثر الحجم والأداء والوصول كمعيار قبول.
