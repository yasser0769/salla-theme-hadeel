> **تصحيح مصدر الحقيقة — 2026-08-10:** يقاس حد النشر على الحزمة المضغوطة المقدّرة
> للثيم مع استبعاد `node_modules`، لا على مجموع بايتات `public/` الخام. الهدف الداخلي
> الحالي 95% من حد 1,000,000 بايت، وتبقى أرقام raw/gzip/network/runtime قياسات مستقلة.

اكتب مواصفة وظيفية لثيم هديل على سلة. هديل ثيم واحد عام بنواة مشتركة وأربعة Presets. ترتيب القرار: زيادة التحويل، ثم سهولة التخصيص وتنوع الأشكال، ثم الجمال والحركة.

**الوصف المبسط:** نحوّل الحجم والسرعة من ملاحظة متأخرة إلى شرط يوقف الدمج والإطلاق عند التراجع.

**القيمة:** يحمي هديل من تجاوز حد سلة ومن أن تصبح كثرة الخيارات سببًا في بطء المتاجر.

**داخل النطاق:**
- ميزانية حجم للحزمة ولكل Pull Request.
- تحليل أثقل CSS وJavaScript وإزالة التكرار والأصول غير المستخدمة.
- تحميل كود كل صفحة عند الحاجة وتقليل الطلبات الشبكية.
- بوابات بناء وفحص وأداء وإمكانية وصول.
- Baseline وRegression report للصفحات الأساسية.
- قواعد قبول أي Dependency جديدة.

**خارج النطاق:**
- تحسينات سيرفر أو CDN خارج سيطرة الثيم.
- إزالة ميزة متفق عليها دون مقارنة قيمتها وتكلفتها.
- الاعتماد على Lighthouse وحده دون فحص تجربة حقيقية.

**المتطلبات التي لا يجوز إسقاطها:**
- تسجيل حجم الحزمة الحالي ثم تحديثه آليًا بعد البناء.
- استخدام 95% كهدف داخلي صحي: ما دونه `PASS`، وما بينه وبين حد سلة `PASS WITH HEADROOM WARNING` بلا استثناء مطلوب، وفوق حد سلة فقط `FAIL`.
- منع الصور والفيديوهات التجريبية من دخول أصول الإنتاج.
- عدم إنشاء طلب مستقل لكل منتج أو عنصر عندما يمكن التجميع أو التضمين.
- توثيق أثر كل ميزة على الحجم والطلبات والرسم والتفاعل داخل plan.
- رفض Dependency جديدة بلا مقارنة مع حل سلة أو حل محلي صغير.
- تشغيل production build وtheme guard قبل القبول.
- قياس الصفحات الرئيسية والمنتج والتصنيف على الجوال والكمبيوتر وفق الدستور.
- إنشاء قائمة Cleanup مرتبة بالأثر بدل إضافة Overrides جديدة فوق الكود القديم.

اجعل المواصفة:
- مفهومة لمالك غير تقني.
- مستقلة وقابلة للاختبار.
- Mobile-first وArabic/RTL-first مع English/LTR parity.
- ملتزمة بدستور `.specify/memory/constitution.md` و`AGENTS.md`.
- تبدأ بفحص الموجود وتصنيف Existing/Build/Spike/Deferred.
- لا تختار تقنية التنفيذ؛ هذا للـPlan.
- تحتوي بوابة Figma إلزامية قبل Plan للواجهات المرئية، مع `design.md` وNode IDs وموافقة المالك.
- تشترط production build وtheme guard ومعاينة سلة الحقيقية.
- تمنع نسخ كود/أصول/هوية Kalles أو رائد.
- تمنع أرقام social proof الوهمية في الإنتاج.
- تذكر أثر الحجم والأداء والوصول كمعيار قبول.
